# 跨会话主动盯盘与高层破局顾问

## 适用场景

1. **跨对话监工与破局诊断**：用户给出另一个正在运行或刚停止的对话（如 `codex://threads/<id>`、Claude Code 会话 ID 或其他工作区对话），要求判断对方是否跑偏、陷入局部死胡同，或要求持续盯防。
2. **本对话长任务主动值守**：当前对话启动了预计耗时 >3 分钟的远程构建、部署、全量回归或外部子任务，需主动跟踪进度直至终态。

## 核心执行原则

### 1. 主动定时巡检（拒绝被动失联）

- 绝不启动后台长任务后静默等待用户来催问（“现在什么情况了 / 超出 9 分钟了 / 主动监控啊”）。
- **优先使用宿主原生定时/唤醒能力**：
  - 在 Antigravity 中：使用原生 `schedule` 工具设置周期性或单次定时器（如内部后台任务每 2～3 分钟检查一次，或按用户指定的“每 15 分钟”定期巡检）。
  - 在 Codex / Claude Code 中：若操作的是外部 `opus-review` / `codex-review` / `dsh-review` / `codex-task` / `opus-task` 任务，优先复用对应技能内置的无模型后台观察器（`opus.py watch`、`codex.py watch` 或 `dsh.py watch`）；若盯防的是独立外部会话且当前宿主无定时器，则在每次回复末尾明确写出当前状态与建议下次检查时间点。
- 任务进入终态（成功完成或明确失败停止）后，立即取消/清理对应的活动定时器，不留孤儿调度。

### 2. 高层破局诊断（拒绝倾倒底层日志细节）

当检查目标对话（如从 `~/.codex/state_5.sqlite`、`~/.codex/sessions/`、`~/.claude/projects/` 或 `~/.gemini/antigravity/brain/` 读取最新进展）时，**不要向用户复述冗长的命令输出或底层代码细节**，每次汇报严格浓缩为以下**三要素**：

1. **【状态与思维局限诊断】**：
   - 一句话说明对方当前停在哪个阶段（运行中 / 已停止待指示 / 报错受阻）。
   - **思维局限（Local Minimum）识别**：检查对方是否在同一个报错、同一个脆弱 workaround（例如反复修补正则、盲目重试超时命令、在错误层级打补丁、违反项目边界硬磕）上连续打转 ≥3 次。若是，直接指出其陷入了什么思维局限，并给出**更高维度的替代解法**（如：改走确定性计算层、换用现有获准通道、砍掉非核心分支）。
2. **【预计耗时与信心度】**：
   - 明确给出：`预计剩余时间：约 X 分钟` 与 `当前完成信心度：XX%`（基于已通过的门禁/步骤占比与剩余风险客观评估）。
3. **【行动建议与一行破局提示词】**：
   - 明确回答：**“现在不需要打扰它”** 或 **“建议立即干预”**。
   - 若需干预，直接提供一段**高浓缩、去细节化、可直接复制发给目标对话的「高效版提示词」**（代码块包裹，3～5 句话以内，直接告诉目标 Agent 停止当前死胡同、切到哪个高层解法）。
