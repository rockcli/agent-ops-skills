# Web Interaction Design

对既有 Web 应用做系统性的交互重设计,而不是零散调样式。核心信念:重设计的产出是**一套设计系统 + 更清晰的信息架构**,不是散落的 CSS 补丁。

## 工作流(按顺序执行,不要跳步)

### 1. 审计现状(先看再改)

- 用浏览器逐页截图,列出每个页面的:首屏传达了什么、主要动作是什么、层级是否清晰。
- 按十条启发式打分(1-5):可见性状态、系统与现实匹配、用户控制、一致性、错误预防、识别而非回忆、灵活效率、审美极简、错误恢复、帮助文档。
- 只对 ≤3 分的问题动手;产出一份简短的问题清单(每条:页面/问题/影响),作为改版依据。

### 2. 定义设计 tokens(先定系统,再写组件)

在 CSS 顶部用 custom properties 定义,所有组件只允许引用 token:

```css
:root {
  /* 色彩:1 个主色 + 中性灰阶 + 语义色;对比度 ≥ 4.5:1(正文) */
  --brand-600: #4f46e5; --brand-700: #4338ca;
  --gray-50: #f8f9fb; --gray-200: #e5e7eb; --gray-500: #6b7280; --gray-900: #111827;
  --ok: #16a34a; --warn: #d97706; --danger: #dc2626;
  /* 间距 4px 基数;圆角两档;阴影两档 */
  --sp-1: 4px; --sp-2: 8px; --sp-3: 12px; --sp-4: 16px; --sp-6: 24px; --sp-8: 32px;
  --radius: 8px; --radius-lg: 14px;
  --shadow-sm: 0 1px 2px rgb(0 0 0 / .06); --shadow-md: 0 4px 12px rgb(0 0 0 / .08);
  /* 字号阶梯:12/13/14/16/18/22/28,行高正文 1.6 */
}
```

- 分类/类型等枚举值分配**稳定的色彩标识**(每个枚举一个色对),全站一致。

### 3. 信息架构与布局

- 每个页面回答:用户 3 秒内看到的第一重点是什么?把主要动作放在视觉动线起点。
- 导航 ≤ 5 项;当前项用 pill/下划线明确标示。
- 列表页 = 筛选器(靠近搜索) + 卡片流;详情页 = 主内容 + 侧栏(作者/操作/元数据);
  长表单 = 分组 fieldset(必填在前) + 底部提交条。

### 4. 组件与状态(缺状态是最大的"欠设计")

每个交互组件必须定义五种状态:**默认 / hover / active(按压) / focus-visible / disabled**;
数据区域必须定义四种:**加载(骨架屏,不是白屏) / 空(说明 + CTA) / 错误(可重试) / 有数据**。
反馈用 **toast**(自动消失)而非行内横幅;破坏性操作需确认。过渡 120-160ms,只动 opacity/transform。

### 5. 可访问性底线

- 焦点环可见(`:focus-visible` 描边);图标按钮有 `aria-label`;
- 切换类控件用 `aria-pressed` / `aria-selected`;颜色不作为唯一信息载体(加文字/图标)。

### 6. 截图验证闭环(必须执行)

- 改完后用浏览器工具逐页截图(默认态 + hover/空态至少抽查),与改版前对照。
- 检查:对齐是否成一线、间距节奏是否一致、字号层级是否 ≤ 4 档/页、空态是否友好。
- 发现问题回到第 2-4 步修 token/组件,而不是写一次性 CSS。

## 反模式(出现即返工)

- 零散 magic number 颜色/间距(绕过 token)。
- 一页超过 4 个字号档或 2 种字体。
- 只设计"有数据"状态,加载/空/错误全裸奔。
- 用 alert/confirm 做常规反馈;行内横幅挤布局。
- 无 hover/focus 反馈的"看起来能点"的元素。
